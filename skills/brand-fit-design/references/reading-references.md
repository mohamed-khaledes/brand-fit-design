# Reading references

The goal is to understand *why* a reference fits the business so you can rebuild that effect with
new parts. Look, measure, then name the principle.

## How to look

- Open each link in a browser tool and screenshot the first screen at desktop width, then scroll to
  one or two characteristic sections. For an image, read the image itself.
- Where you can run JavaScript on the page, read computed styles for exact values: the body and
  heading `font-family`, `font-size`, `line-height`, `letter-spacing`; the background and text colours
  of the hero and one section; the main button's radius and padding; the content `max-width`.
- Don't pull more than a few pages per reference. Two screenshots usually tell you enough.

## Digest per reference (keep each to ~8 lines)

```
### <name> (<url or file>) - developer likes: <their words>
Palette: ground #.. · ink #.. · accent #.. (how much accent: a touch / a lot)
Type: <family/character: geometric sans, high-contrast serif, condensed grotesk...>, hero size ~..px, weight, tracking
Layout: grid/width, alignment (left/centre), density, how sections are separated (space, colour bands, rules)
Imagery: photo / product / UI / illustration; crop, light, colour grading, people or not
Shape: radius, borders, shadows, buttons
Motion: none / subtle hover / one load moment / scroll-driven
Copy tone: short and plain / warm / technical / luxurious; headline length
What makes it fit its business: one sentence
```

## Then synthesize

- **Common ground:** what two or more references share. This is the developer's taste; the brief
  follows it.
- **Borrow list:** the specific parts the developer named, each restated as a principle ("large
  uncropped product on a flat warm ground", not "copy the Aesop hero").
- **Leave out:** anything that fits the reference's business but not this one (a luxury brand's
  sparse copy on a page that must explain a service; a game studio's effects on a clinic).
- **Gap check:** what the business needs that no reference shows (a menu, a booking form, pricing).
  Design it in the references' language.

## Never

- Copy markup, CSS, copy, photos, illustrations, logos or a signature effect from a reference.
- Reproduce a reference's exact layout section by section. Same family, different page.
